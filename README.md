# 신축 아파트 하자 보수 현황

신축 아파트 사전점검에서 발견한 하자와, 건설사가 어디까지 수리했는지를
가족(부모님)이 휴대폰으로 쉽게 볼 수 있도록 만든 단일 페이지 웹사이트입니다.

- **1차 점검**: 2026-05-09~10 (전문 점검) · **79건**
- **2차 점검**: 2026-07-02 · **42건** (신규 접수)
- **시공사**: DL이앤씨 (e편한세상 검단 웰카운티)
- **전체 121건** — 공간별로 "수리 완료 / 아직 남은 곳"을 나눠 보고, 보수 전·후 사진 + 건설사 답변 + AI 보수 판단까지 확인

> 🔒 공유용으로 동·호 등 개인 식별정보는 넣지 않았습니다. (DL 등록번호는 건설사 시스템 대조용으로만 유지)

## 화면 구성

- **📊 수리 현황(홈)** — "우리 집 하자, 어디까지 고쳐졌나요?"
  - 상단 **진행 퍼널**: 전체 121건 → **✅ 수리 완료 57** / **🚩 아직 남은 곳 64**(조치 예정·하자 아님·접수 대기로 분해)
  - **📍 공간별 수리 현황** — 공간마다 `✅완료 N · 🚩남음 N` 배지, 남은 곳 많은 순 정렬. 눌러서 드릴다운.
- **차수 필터** — `전체 / 1차 / 2차` 칩으로 전환(기본 전체 합산). 1차엔 보수 전·후 사진과 건설사 답변이, 2차(신규 접수 42건)엔 현재 사진이 표시됩니다.
- **🚩 아직 남은 곳** — 미완료 + 건설사가 '하자 아님/조치 예정'으로 답변한 항목만 모아보기 (재요청·재이의 준비용, CSV 내보내기 지원).
- **공간 화면(드릴다운)** — 그 공간을 `🚩 아직 남은 곳` / `✅ 수리 완료` 두 섹션으로 분리해 카드로 표시. 왼쪽 메뉴에서 같은 공간을 다시 누르면 접힙니다.
- **상세** — 카드/항목을 누르면 위→아래 순서로:
  1. **건설사(DL이앤씨) 처리 상태** — 수리 완료 / 건설사: 조치 예정 / 건설사: 하자 아님 / 접수·대기 (+ 건설사 답변 원문)
  2. **🔗 교차검증** — 같은 부위·유형의 1차↔2차 항목을 서로 연결(예: 실외기실 전등 1차 ↔ 2차 재접수). 눌러서 사진·상태 비교.
  3. **보수 전 · 후 사진 좌우 비교** (사진을 누르면 원본 화질로 확대)
  4. **🤖 AI 보수 판단** — 사진을 비교한 독립 판정 + 근거 (참고용)
  5. **식별 정보**(공간 · 부위 · 결함유형 · DL등록번호) + `🔧 DL 보수시스템에서 열기` 버튼

가독성을 위해 본문 글자 20px, 어려운 용어를 줄였고, 안드로이드(갤럭시)·iOS(아이폰)·맥에서 모두 동작하도록 `dvh`·`viewport-fit=cover`·safe-area를 적용했습니다.

## 🤖 AI 보수 판단 (2단계 검증)

"건설사가 after 사진을 올렸다 = 실제로 고쳐졌다"가 아니므로, 각 하자의 **보수 전/후 사진을 AI가 직접 비교**해 판정합니다 (`verdicts.js`).
1차로 '보수 확인' 판정한 항목은 **다른 AI로 한 번 더 교차 재검증**해, 사진만으로 확실치 않은 건은 '확인 어려움'으로 낮췄습니다.

| 판정 | 의미 | 건수 |
|------|------|----:|
| ✅ 보수 확인 | 전→후 사진에서 결함이 해소된 게 보이고, 재검증에서도 유지 | 14 |
| ❓ 사진으로 확인 어려움 | 기능성 결함(난방·흔들림·개폐 등)이거나 각도·거리 탓에 판단 불가 (재검증 하향 8건 포함) | 38 |
| ❗ 미보수 의심 | 후 사진에도 결함이 남아 보임 | 5 |
| ⬜ 보수 후 사진 없음 | 작업 후 사진 미등록 (1차 22 + 2차 신규 42) | 64 |

> 사진 기반 자동 추정이므로 **참고용**이며, 최종 확인은 직접 점검을 권장합니다.

## 파일 구조

| 파일 | 설명 |
|------|------|
| `index.html` | 메인 페이지 (디자인 + 동작 전부 포함) |
| `data.js` | 하자 데이터 121건 (`ITEMS`, `STATS`) — `round`(1/2), 건설사 답변(`dlReply`) 포함 |
| `verdicts.js` | 하자별 AI 보수 판단 (`VERDICTS`) |
| `images/` | **원본 고화질** 보수 전/후 사진 — `images/{등록번호}/before_*.jpg`, `after_*.jpg` (탭하면 원본 확대) |
| `thumbs/` | 화면 표시용 **썸네일**(긴 변 768px) — 목록·상세에서 빠르게 로딩 |
| `.nojekyll` | GitHub Pages가 폴더를 그대로 서빙하도록 하는 표시 파일 |

> 목록·상세 화면은 가벼운 `thumbs/`로 빠르게 보여주고, 사진을 누르면 `images/`의 **원본 화질**(하자보수 분쟁 대비 증거용)로 확대됩니다.

## 유지보수 — 보수 사진이 추가로 등록되면

DL 시스템에 새 작업후 사진이 올라오면 다음 순서로 갱신합니다.

1. `images/{등록번호}/after_*.jpg` 원본 추가
2. 같은 파일을 긴 변 768px 썸네일로 변환해 `thumbs/{등록번호}/after_*.jpg` 추가
   - 예: `python3 -c "from PIL import Image,ImageOps; im=ImageOps.exif_transpose(Image.open('images/SYS/after_1.jpg')).convert('RGB'); im.thumbnail((768,768)); im.save('thumbs/SYS/after_1.jpg','JPEG',quality=80,optimize=True)"`
3. `data.js`의 해당 항목 `hasAfter:true`, `after:[...]`, `repairDate:"YYYY-MM-DD"` 수정
   - 화면 통계(완료/남음)는 `index.html`이 `ITEMS`에서 자동 재계산됩니다.
4. `verdicts.js`의 해당 `VERDICTS[등록번호]`를 새 사진 기준으로 재판정
5. `git add -A && git commit && git push`
