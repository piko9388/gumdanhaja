## 화면 구성

- **왼쪽 메뉴 (드릴다운)** — 모바일에서는 `☰` 버튼으로 열리는 서랍
  - `🏠 전체 현황` · `⚠️ 점검이 필요한 곳`(미보수 의심+사진 없음 모아보기) · 공간별 그룹
  - **`🔥 바닥 난방 (전 공간)`** — 전 공간 공통 난방 결함 8건을 별도 그룹으로 최상단에 (DL이 '주방/식당 분배기'로 묶어 둔 것을 사용자 관점으로 재정리)
  - 공간을 펼치면 그 안의 하자 목록이 **식별 라벨**(부위 · 결함유형 · DL번호)과 함께 표시 (DL 원본 위치는 상세 식별정보에 그대로 유지 → 업체 대조용)
- **홈** — 인사말 + 진행 상황 요약
  - 통계 3분할: 전체 79 / 사진으로 확인됨 57 / 사진 준비중 22
  - 비교 막대: **건설사 완료 처리 77곳 → 사진으로 확인 가능 57곳** (한눈에)
- **공간 화면** — 메뉴에서 공간 선택 시 그 공간의 하자 카드 목록 (카드마다 🤖 AI 판단 배지)
- **상세** — 카드/메뉴 항목을 누르면 위→아래 순서로:
  1. **건설사(DL이앤씨) 처리 상태** — 보수 완료 / 사진 준비중 (+ 보수 등록일)
  2. **보수 전 · 후 사진 좌우 비교** — 왼쪽 전 / 오른쪽 후 (사진 준비중이면 현재 사진)
  3. **🤖 AI 보수 판단** — 사진을 비교한 독립 판정 + 근거 + 참고용 안내
  4. **식별 정보**(공간 · 부위 · 결함유형 · DL번호) + **`🔧 DL 보수시스템에서 열기`** 버튼
  - 사진을 누르면 원본 화질로 전체화면 확대

가독성을 위해 본문 글자 20px, 어려운 용어 없이 표현했고, 안드로이드(갤럭시)·iOS(아이폰)·맥에서 모두 동작하도록 `dvh`·`viewport-fit=cover`·safe-area를 적용했습니다.

## 🤖 AI 보수 판단

"건설사가 after 사진을 올렸다 = 실제로 고쳐졌다"가 아니므로, 각 하자의 **보수 전/후 사진을 AI가 직접 비교**해 4가지로 판정합니다 (`verdicts.js`).

| 판정 | 의미 | 건수 |
|------|------|----:|
| ✅ 보수 확인 | 전→후 사진에서 결함이 해소된 게 보임 | 22 |
| ❓ 사진으로 확인 어려움 | 기능성 결함(난방·흔들림·개폐 등)이거나 사진이 부위를 안 보여줌 | 30 |
| ❗ 미보수 의심 | 후 사진에도 결함이 남아 보임 | 5 |
| ⬜ 보수 후 사진 없음 | 작업 후 사진 미등록 | 22 |

> 사진 기반 자동 추정이므로 **참고용**이며, 최종 확인은 직접 점검을 권장합니다.

## 파일 구조

| 파일 | 설명 |
|------|------|
| `index.html` | 메인 페이지 (디자인 + 동작 전부 포함) |
| `data.js` | 하자 데이터 79건 (`ITEMS`, `STATS`) |
| `images/` | **원본 고화질** 보수 전/후 사진 218장 — `images/{등록번호}/before_*.jpg`, `after_*.jpg` (탭하면 원본 확대) |
| `thumbs/` | 화면 표시용 **썸네일**(긴 변 768px) — 목록·상세에서 빠르게 로딩 |
| `.nojekyll` | GitHub Pages가 폴더를 그대로 서빙하도록 하는 표시 파일 |

> 목록·상세 화면은 가벼운 `thumbs/`(약 10MB)로 빠르게 보여주고, 사진을 누르면 `images/`의 **원본 화질**(2~5년 하자보수 분쟁 대비 증거용)로 확대됩니다.

## 배포 방법 (GitHub Pages)

1. 이 저장소에 코드와 `images/` 폴더가 모두 올라간 상태에서
2. **Settings → Pages**
3. **Source**: `Deploy from a branch`
4. **Branch**: `main` / 폴더 `/ (root)` → **Save**
5. 1~2분 뒤 `https://piko9388.github.io/gumdanhaja/` 접속
